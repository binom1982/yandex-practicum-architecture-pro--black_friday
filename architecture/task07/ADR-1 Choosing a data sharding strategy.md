#### Логика принятия решений

1. Коллекция orders (Ключ: customer_id, Hashed):
   * Шардирование по customer_id, для того, чтобы все заказы одного пользователя попали в один шард, чтобы исключить опрос всех шардов. Необходимо для быстрого поиска истории заказов конкретного пользователя.
   * Хеширование удовлетворяет P-2 , распределяя клиентов равномерно по шардам
2. Коллекция products (Ключ: product_id, Hashed):
   * Шардирование по product_id, чтобы все товары попадали в один шард для эффективного списания остатков
   * Необходимо для быстрого просмотра товара
   * Для "Поиск товаров по категориям и фильтрация по диапазону цен" будет необходимо опрашивать все шарды, тк по полям category и price нет шардирования
3. Коллекция carts (Ключ: owner_id, Hashed):
   * Шардирование по owner_id - унификация доступа для гостей и пользователей
   * Добавление/замена/удаление товара в корзине, все данные на одном шарде
4. Соблюдение ограничений:
   * Выбор неизменяемых полей в качестве ключей учитывает ограничение +R-1
   * Индексы строятся с учетом ограничения +R-2
