### Операции чтения

| **Коллекция** | **Операция**                                                   | **Источник чтения** | **Обоснование**                                                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| products                     | Просмотр каталога, поиск, карточка товара | Secondary                               | Допустима временная неактуальность (цена, описание). Снижение нагрузки на Primary.             |
| products                     | Проверка остатков (перед оплатой)                | Primary                                 | Критично избежать оверселлинга. Требуется строгая консистентность.                                |
| orders                       | История заказов (список)                                 | Secondary                               | Допустима задержка отображения архивных данных.                                                                    |
| orders                       | Статус заказа (сразу после действия)           | Primary                                 | Пользователь ожидает мгновенного отражения изменения состояния.                                     |
| carts                        | Просмотр, добавление, удаление товаров      | Primary                                 | Высокая частота изменений. Риск рассинхронизации данных внутри сессии пользователя. |

### Допустимая задержка репликации

* Для Secondary: до  5 секунд (3 сек (техническая задержка) + 2 сек (буфер) . Достаточно для обновления каталога и истории, не критично для пользовательского опыта.
* Для Primary: 0 секунд (актуальные данные).

### Обоснование выбора

1. **Консистентность:** Критичные данные (остатки, статусы, корзина) требуют сильной консистентности для предотвращения бизнес-ошибок (продажа отсутствующего товара, потеря данных корзины).
2. **Частота обновлений:** Каталог товаров меняется редко — подходит для Secondary. Корзина и статусы меняются часто в рамках сессии — требуют Primary.
3. **Бизнес-логика:** Риск потери клиента из-за неактуальной корзины выше, чем риск показа устаревшей картинки товара. Нагрузка распределяется на Secondary там, где это безопасно.
