### Логика принятия решений

**Метрики мониторинга:**
Выбраны метрики `mongodb_ss_metrics_operations_total`, `mongodb_ss_mem_resident`, `mongodb_ss_global_lock_current_queue`. Они напрямую отражают нагрузку на CPU, I/O и память шарда. Порог алерта установлен в 20% отклонения между узлами.

**Стратегия шардирования:**
Для коллекции `products` ключ шардирования оставлен без изменений (`{ product_id: "hashed" }`).

* Если бы был выбран ключ (`{ category_id: "hashed" }`), то он мог создавать горячие точки из-за популярности «Электроники».
* Хеширование гарантирует равномерное распределение документов независимо от категории товара.

**Механизмы балансировки:**

1. **Balancer:** Включен для фоновой поддержки баланса.
2. **Resharding:** Используется для глобального изменения ключа шардирования без дамп/рестора.
3. **Manual Move:** Оставлен как аварийный инструмент для срочного снятия нагрузки.

## **Альтернативы**

**Шардирование по категории (`category`):**

* **Плюсы:** Запросы по категории выполняются на одном шарде (targeted query).
* **Минусы:** Нарушает P-1. Популярные категории создают «горячие шарды». Отклонено.

**Ручное управление чанками (без Balancer):**

* **Плюсы:** Полный контроль над расположением данных.
* **Минусы:** Высокая операционная нагрузка, медленная реакция на всплески трафика. Отклонено в пользу автоматизации.

**Вертикальное масштабирование горячего шарда:**

* **Плюсы:** Быстрое решение без миграции данных.
* **Минусы:** Имеет физический предел, дорого, не решает проблему архитектурного дисбаланса. Отклонено.

### Недостатки, ограничения, риски

**Нагрузка во время миграции (Производительность):**

* **Риск:** Команда `reshardCollection` потребляет ресурсы CPU и сети, возможно замедление работы кластера.
* **Митигация:** Выполнение миграции в окно наименьшей нагрузки (night window). Мониторинг лага репликации.

**Scatter-Gather запросы (Производительность):**

* **Риск:** При шардировании по `product_id: hashed` запросы по категориям требуют опроса всех шардов.
* **Митигация:** Внедрение кэширования популярных категорий (Redis). Направление поисковых запросов на Secondary реплики.

**Неизменяемость шард-ключа (Ограничение):**

* **Риск:** Повторное изменение ключа шардирования в будущем будет дорогостоящей операцией.
* **Митигация:** Текущий ключ `hashed` является универсальным для равномерной записи. Дальнейшие изменения маловероятны.
